## 1.0.0 历史工具限制（1.0.2 已补齐真实拖放）

真实跨窗口坐标拖放没有完成验收。CUA 的 drag 触发了原生 `NSDraggingSession`，但后续目的点操作返回 `windowNotFoundAtPosition`，未取得目标窗口的 draggingEntered / perform 回调证据。Escape 可取消。不能把源码中的整窗接收区域或程序化文档移动测试当成“鼠标拖入任意区域已通过”。

尚待手工补充：单/多标签所有组合的实际放下，拖入正文、预览、侧边栏、状态栏和标题/工具栏，拖出拆窗、标签间重排、连续切换的高帧率闪烁观察，以及真实键盘中文输入法候选确认。

原生 NSTextInputClient 组合文本（marked text）开始/提交与 Unicode 修改已由自动集成检查覆盖；它不能替代真实输入法候选窗口验收。

测试时一次从 `/tmp` 签名构建路径启动后，CUA 对系统打开面板连续超时；进程 CPU 为 0，未修改文档。尝试恢复失败后，仅结束该隔离测试实例，改回项目内路径继续，并取得后续正常退出证据。没有结束用户其他应用，没有清理偏好或系统缓存。原生系统打开/保存面板由 macOS 管理，可能记忆导航位置；TinyEditor 自有偏好、最近记录和草稿使用隔离存储。

最终退出测量发现旧异步退出路径会使隔离测试主进程遗留，期间出现过两个独立隔离命名空间的测试进程。确认全部内容为自动夹具后结束它们，修复干净文档直接退出、运行循环确认和重复退出保护；最终重新顺序执行核心/集成/启动检查，65 项通过且 normalExit=true。启动测量四个主进程均正常退出，之后通过进程快照确认没有测试主进程，再启动唯一正常模式应用。

最终正常模式窗口右键菜单仅显示“复制 Markdown / 复制整个文档 Markdown／源码 / 全选”；执行整篇源码复制后 pbpaste 与 README.md 字节一致，文档保持干净。
