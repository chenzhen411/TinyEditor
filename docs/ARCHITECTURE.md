# TinyEditor 架构

应用代码与 TE 图标在当前 Mac 独立实现。最低部署版本 macOS 13；本次交付 arm64。AppKit、TextKit 1、WebKit、CryptoKit 为系统框架，不嵌入浏览器运行时。

## 文档与窗口

`EditorDocument` 持有权威 `NSTextStorage`、文件身份、原编码、磁盘摘要、行索引和 `UndoManager`。标签移动直接转移该对象。源码视图按需创建并保留，各自拥有非连续布局的 `NSLayoutManager`。高亮仅写布局管理器的临时属性，不进入撤销记录。

每个 `EditorWindowController` 管理独立的文档数组、活动标签、侧边栏宽度、表格滚动与选择。目标视图先布局并显示，再从源窗口移除。拖动使用每次随机的进程内令牌，并核对 `draggingSource`；拖入类型由窗口在创建时注册，窗口与委托处理拖动消息；frame view 上的提示层仅绘制且始终穿透鼠标。拖动源标签由上下文强引用到结束回调，结束时先清理再进行拆窗。

## 超长行

初始原型对 10 MB 单行排版耗时约 6.8 秒，编辑约 2 秒，因此不能直接沿用多行文件策略。当任一逻辑行超过 100,000 个 UTF-16 单元时，源码区改用 32,768 单元左右的原生分段视图；边界对齐组合字符。权威原文仍完整保存在文档存储中，分段编辑转换为原文范围的修改和逆操作。分页切换与窗口间移动保留同一撤销管理器。

分段条明确显示原文位置，并提供前后段按钮。查找和替换在完整原文上执行，查找命中后定位到相应分段。全选复制、保存、编码转换与预览使用完整原文。鼠标只能在当前段中连续选择；跨段精确范围选择尚无专门 UI，这是明确的性能折中。

## Markdown

离线打包 markdown-it、Mermaid tiny、KaTeX、DOMPurify 与 highlight.js。Node/npm/esbuild 仅用于开发时更新依赖，普通构建直接使用已提交资源，运行时不需要。

解析器为块节点保存源逻辑行范围，再映射到未经换行标准化的原文 UTF-16 偏移。未变化的普通文本节点可精确复制子串；涉及语法的选区保守扩展至完整源码块，跨块复制取连续原文范围，全选复制直接取完整原文。原始 CRLF、实体拼写、转义、围栏及 HTML 原文不会由 DOM 反向生成。复制操作统一发给原生端，仅写纯文本剪贴板类型。

HTML 经 DOMPurify 过滤；CSP 禁止网络脚本、连接与嵌入。图片在插入 DOM 前移除 src，原生端批准后才能加载。远程图片默认关闭，本地资源使用专用 URL scheme，限制在规范化文档目录下、检查符号链接，只提供不超过 20 MB 的位图。相对文档链接也限制在文档目录内。

Mermaid tiny 官方精简版不包含 mindmap、architecture 图和 Mermaid 内嵌 KaTeX；文档级数学公式由单独 KaTeX 支持。不能渲染的图表显示错误与原文，不影响其余文档。

## 保存与恢复

读取 UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM 和 GB18030，拒绝明显二进制或无法无损往返的内容。保存保持原编码与换行，采用文件协调与原子替换。每次保存前重新读取 SHA-256 版本摘要；后台通过时间、大小和 inode 变化检查外部原子替换。存在本地修改则进入冲突保护，只允许保留编辑、重新载入或另存为。

恢复草稿防抖写入 Application Support/TinyEditor/Recovery；已处理记录标记 resolved。测试通过 `TINYEDITOR_DATA_DIR` 使用独立 JSON 偏好与恢复存储，禁用系统窗口尺寸持久化，不清空正常数据。

## 单实例

在创建 NSApplication 前取得每用户 `flock` 锁。第二进程经权限为 0700 的本地目录中的 Unix socket 转交带 UUID 的请求，收到确认后退出。主进程去重并排队请求；内核在崩溃后释放锁。固定应用标识和 IPC 路径使不同安装位置复用主实例。隔离验证使用独立 IPC 命名空间，仅用于避免接触正常用户数据。
