# 1.0.1 拖拽与鼠标操作回归

## 已修复的机制

- 源标签视图由拖拽上下文强引用到 AppKit 的 ended 回调，避免重建标签栏/关闭源窗口时丢失回调。
- 内部标签类型由 NSWindow 在窗口创建时注册；接收不依赖临时覆盖视图的鼠标命中。
- 覆盖视图仅绘制轻量提示，hitTest 无条件穿透，即使残留拖动状态也不能挡住关闭按钮、编辑区域或标题栏控件。
- 放下前先标记 accepted；结束时先清理上下文再拆窗。拖到其他 TinyEditor 窗口内不会误拆窗。
- 活动标签持续显示关闭按钮，按实际按钮矩形命中；标签作为无障碍容器暴露独立关闭按钮。
- 侧边栏展开显式调整 split view，保护首选宽度并防止重入布局。

## 本轮真实操作记录

已使用普通鼠标坐标点击（非直接模型调用）验证：标题栏按钮展开侧边栏；第二个标签关闭按钮移除正确标签；Escape 后侧边栏仍能收起；有修改的标签关闭时出现原生保存确认，取消后原文和修改标记保留。

跨窗口拖动的最终结果与证据将在完成后追加，不预先记为通过。

## 自动回归结果

73 / 73 集成检查通过，exitCode=0、normalExit=true。新增检查覆盖源标签在标签栏重建和源窗口关闭后的存活、显示拖入提示时关闭按钮与工具栏的真实 AppKit hitTest、原生按钮展开/收起侧边栏和原生关闭按钮仅移除正确标签。数据核心 3,061 条断言通过。

回归中另发现普通鼠标结束事件读取 keyCode 会触发 AppKit 异常。已先判断 keyDown/keyUp，再读取键码；鼠标结束路径现在完成清理。

## 真实放下仍受限

第二轮 CUA 拖动日志仅收到 begin，没有 movedTo、目标 candidate/entered 或正常放下回调；Escape 后收到 ended，escape=true，两个窗口与文档身份保留。改为窗口/委托双入口并修正结束事件后仍如此。没有以模型移动检查冒充真实放下通过。

因此正文、Markdown 预览、工具栏真实放下，以及拖出拆窗尚未记为通过。已请求允许用本机 CGEvent 发送真实系统输入；截至本轮打包尚未收到授权，没有调用 CGEvent 注入。该确认来自电脑控制工具“其他 UI 输入技术须用户明确要求”的规则。

原始日志与状态位于 `docs/evidence/1.0.1-*`。正常点击与 Escape 已实测；完整真实跨窗矩阵等待授权后继续。

接收方式参考 [Apple NSWindow.registerForDraggedTypes](https://developer.apple.com/documentation/appkit/nswindow/registerfordraggedtypes(_:))，原生窗口会成为拖入目标，相关消息也可由窗口委托处理。
