# TinyEditor 1.0.2 真实拖放与标签验收

2026-10-29；macOS 27.2（26B123），Apple Silicon / arm64；Release build 3。

## 修复结果

标签改为平直分区：活动标签使用正文底色，非活动标签使用轻微灰色背景及短分隔线，移除圆角描边框，缩小关闭符号。激活文档时立即刷新标签文字、底色和关闭按钮，不再等待鼠标悬停或下一次编辑。

实际系统拖动复现了窗口级接收的缺口：统一标题/工具栏可以放下，WebKit 正文不触发目标回调。最终在窗口创建时提前安装注册了私有标签类型的透明原生拖放视图，转发到同一窗口接收逻辑。该视图的普通鼠标 hitTest 始终返回 nil，拖动期间也不捕获正常点击。保留随机 token、源对象身份校验、源标签生命周期与稳定文档/UndoManager。

## 方法与证据

本轮使用用户明确授权的独立 CGEvent 输入驱动，通过 WindowServer 发送真实鼠标按下、移动、放下和键盘事件。只操作隔离测试窗口；数据目录为 /tmp/TinyEditor-102-CG-e 和 /tmp/TinyEditor-102-CG-final。没有调用文档移动方法模拟这些拖动。

原生 AppKit 回调在 [事件日志](evidence/1.0.2-real-drag.log) 中，最终构建复验在 [最终日志](evidence/1.0.2-final-drag.log) 中。每步 JSON 记录窗口、文档 UUID、原文、修改状态、撤销/重做、格式、预览状态和选区。最初失败的预览正文放下及工具栏对照保留在 [失败复现日志](evidence/1.0.2-first-drag.log)。

## 最终构建追加验收

- .txt 文件手动选择 JSON 后跨窗拖入 Markdown 预览；格式、未保存原文和撤销状态完整保留。
- 跨窗后真实 ⌘Z 回到已保存内容，修改标记清除；⌘⇧Z 恢复原文和修改标记。
- 加号创建第三标签后，不移入该标签也立即显示其活动底色和关闭按钮。真实点击第三标签关闭按钮，前两个文档 UUID 保留且仅第三个被移除。
- 真实点击第二标签关闭按钮，原生提示明确为“要保存对 source.txt 的更改吗”；点击取消后原文、修改状态、JSON 格式与撤销链保留。
- 浅色、深色、跟随系统逐次操作；本会话中对两标签、三标签、活动底色、关闭按钮、行号、侧边栏和状态栏的原生截图进行复核。
- 最终构建再次在展开侧边栏、手动 JSON 模式和未保存编辑状态下执行窗口外 Escape，完整窗口/文档快照相同。

追加状态为 evidence/1.0.2-final-*.json。输入驱动的临时设备控制权限在验收后关闭；[撤销复核](evidence/1.0.2-driver-revoked.json) 中 trusted=false、postAccess=false。其他应用权限未修改。驱动不包含在 TinyEditor.app 或 ZIP 内。

## 复测入口与边界

普通应用不需要输入控制权限。只有另行授权真实输入验收时才使用可选驱动：先运行 scripts/build-input-check.sh，再从项目 artifacts/TestSupport 中手动授权固定版本，使用 scripts/run-input-check.py；不要在获得权限后重编译驱动。临时目录应用曾无法被 TCC 按 ID 解析，重编译 ad hoc 驱动也曾使签名绑定失效，这些问题均通过正常应用登记和原生移除/重新添加解决，没有编辑权限数据库。

尚未验证：macOS 13–26、Intel/Universal、真实中文输入法候选窗口、多 MB Markdown、连续切换的高帧率闪烁视频，以及侧边栏长列表物理滚动/选择和拖动调宽的完整矩阵。此记录不把这些范围升级为通过。应用仍为 ad hoc 本地签名，未公证。
